Azure Cloud Infrastructure In Progress

Presentation & Lab Guide — VM Connectivity, Web Hosting, Auto-Shutdown

OSYCL Course

Project Overview

About the Project

A comprehensive Azure Cloud Infrastructure presentation and lab guide developed as a two-person school project. The guide covers practical Azure topics through step-by-step demonstrations: connecting to virtual machines using multiple methods, hosting a website behind a reverse proxy, configuring auto-shutdown, and working with free-tier Azure VMs.

Team

Simon Max, Würth Eric

Topics Covered

VM Connectivity

The lab walks through five distinct connection methods for reaching an Azure VM, demonstrating when and why each one is used:

• Azure Bastion — browser-based SSH/RDP without exposing the VM to the public internet.

• External SSH — classic SSH from a local machine via the VM's public IP.

• Azure Cloud Shell (public IP) — browser terminal reaching the VM through its public IP.

• Cloud Shell with VNet integration — Cloud Shell injected into a private subnet via an Azure Relay Namespace and Network Profile, allowing access to a VM with no public IP.

• Jump Host — a second VM with a public IP used as a stepping stone to SSH into the private VM.

• SSH Key authentication — setting up key-based SSH on both new and existing VMs.

Web Hosting with a VM

Demonstrates a DMZ-style two-VM web hosting architecture:

• VM1 acts as the web server (nginx), fully private with no public IP.

• VM2 acts as the reverse proxy (nginx), the only internet-facing entry point, forwarding HTTP traffic to VM1 over the private network.

• This isolates the web server from direct internet access, so attackers cannot reach it even if they discover its private IP.

Auto-Shutdown

Covers configuring the Azure auto-shutdown feature to automatically power off a VM at a scheduled time daily — a cost-saving measure to avoid charges from VMs left running overnight.

Free Account Virtual Machines

Step-by-step guide to creating free-tier Azure VMs, including the available OS images, VM sizes (B1s, B2ats_v2), the 750-hour shared monthly limit, and the key restrictions of the free tier.

Azure Resource Visualizer

Explains the built-in Azure Resource Visualizer tool, which generates an interactive node graph of all resources in a Resource Group and their connections — useful for checking the architecture at a glance without opening each resource individually.

Technical Stack

Microsoft Azure

The entire lab runs on Azure. Core services used include Virtual Machines, Virtual Networks, Network Security Groups, Azure Bastion, Azure Relay, Azure Container Instances, and Public IP addresses.

nginx

Used in two roles: as a reverse proxy on VM2 (forwarding external requests to VM1) and as the web server on VM1 (serving the HTML content). Configuration is done by editing the nginx sites-available file.

Azure Relay & Cloud Shell VNet

An Azure Relay Namespace and Network Profile are deployed via ARM templates to allow Cloud Shell to connect to a private VM. The Relay creates an outbound HTTPS/WebSocket tunnel into the VNet — no inbound firewall rules needed.
